# Баннер для сайта

Выполни запрос «баннер для сайта <URL или домен>» полностью: посмотри реальный сайт, подбери совместимые цвета, создай или обнови его запись «Баннеры сайтов» в CMS PaulIsLava, опубликуй и верни готовый код для вставки в футер. Например: «баннер для сайта времякарьеры.рф». Пример в запросе о сохранении скилла сам по себе не означает создание баннера.

## Исследование сайта и палитра

Открой сайт во встроенном браузере Codex с пользовательским профилем. Для домена без схемы начни с HTTPS; Unicode-домен допустим, при сопоставлении записей нормализуй hostname через URL (punycode). Посмотри главную и футер, скриншот и фактические CSS-цвета доступного DOM. Не выбирай палитру по имени сайта или памяти.

Определ футера, основной цвет текста, границы и фирменные акценты. Фон и рамка у всех баннеров прозрачные; backgroundColor и borderColor не задавай. Выбери textColor и контрастные brandColor, automationColor, siteColor, chatbotColor, developmentColor в формате #RRGGBB. Сохраняй стиль сайта, но различай услуги оттенками. Префиксы «Создано »/«Заказать » остаются нейтральными, PaulIsLava и названия услуг — акцентными. Бренд по умолчанию PaulIsLava: не заменяй его названием партнёра. Если сайт недоступен, сообщи об этом; не утверждай, что цвета сняты с него. Используй доступные материалы или явно обозначенный предварительный вариант.

## Настройки в Strapi

Перед действиями прочитай [описание реализации](../../../ai/features/partner-footer-banners.md). Схема: packages/cms/src/api/footer-banner/content-types/footer-banner/schema.json.

CMS: https://cms.paulislava.space. Коллекция api::footer-banner.footer-banner. Найди запись по нормализованному websiteUrl, включая черновики; переиспользуй её без изменения bannerKey, не создавай дубликат. При нескольких совпадениях не меняй все записи: выбери действующую опубликованную или уточни существенную неоднозначность.

Заполни name (название сайта), websiteUrl (полный origin HTTP(S), без query/fragment), enabled=true, brandText=PaulIsLava и выбранные цвета. Для автогенерации GIF поле gif должно быть пустым. Если в существующей записи загружен ручной GIF, не удаляй его молча: объясни, что он переопределяет настройки, и согласуй переход на автоматический. bannerKey и embedHtml генерирует сервер, вручную их не составляй и не перезаписывай.

Используй текущую авторизованную админку либо официальный REST API с настроенным STRAPI_API_TOKEN из packages/web/.env.local. Секреты не выводи и не записывай в результаты. При API чтении используй GET /api/footer-banners; создание POST /api/footer-banners?status=published, обновление PUT /api/footer-banners/:documentId?status=published, тело {data: {...}}. Проверь фактический publishedAt: сохранённый черновик не является опубликованным баннером. При неизвестном результате записи сначала перечитай запись, затем решай о повторе.

## Проверка и результат

Прочитай сохранённый embedHtml из CMS. Проверь опубликованную конфигурацию https://paulislava.space/api/banners/<bannerKey> и изображение /api/banners/<bannerKey>/image: HTTP 200, image/gif и действительный GIF. Цвета текста и websiteUrl должны соответствовать выбранным. При ручном GIF endpoint может редиректить на медиа. После обновления учитывай HTTP-кеш до 60 секунд.

Проверь код: обычная HTML-ссылка, noscript с alt и loading=lazy, внешний banner.js с идентификатором записи и адресом сайта. Целевой путь /zakazat-sait-avtomatizaciyu временно редиректит на главную; UTM source содержит hostname партнёра, medium=footer_banner, campaign=made_by_paulislava, content=bannerKey. Не меняй общую анимацию для отдельного сайта: JS уже ждёт две секунды полной видимости, GIF содержит начальную задержку и мигающий курсор.

Выдай пользователю полный embedHtml одним блоком кода html без сокращений и плейсхолдеров — он должен быть готов к вставке. Коротко назови выбранные цвета и поясни, что последующие изменения опубликованных настроек не требуют замены кода. При работе через браузер сохрани скриншот результата и приложи его. Не устанавливай код на партнёрский сайт без отдельного запроса и не обещай рост поискового трафика.

В конце зафиксируй созданный баннер и причины выбора палитры в ai/FEATURES.md и Obsidian по правилам проекта, без секретов. Если менялись только данные CMS, деплой кода не нужен.
