# Сайт на Windows-ПК через FRP

`paulislava.space` обслуживает `PaulislavaWeb` на ПК `DESKTOP-NGNE28E`. Отдельный WSL2 `PaulislavaWeb` работает от LocalService; VHDX, Docker и данные находятся в `E:\Services\PaulislavaWeb`. Windows SCM запускает службу автоматически. Next.js слушает Windows loopback `127.0.0.1:13000`. Образ `web-8b818ca6d6d35ebe386fc252e3ade1bdc9de1ca6` закреплён digest `sha256:515a475e7b56207fa147e0904629bba93d9f64f43a1d5b694f3863d6535a8ac4`; архитектура и слои совпали с резервным контейнером. CMS использует существующую службу `PaulislavaCMS`.

`PaulislavaWebFRP` использует отдельную identity и порт 24008 на loopback VPN-сервера. Nginx на `13.143.194.252` выбирает TLS по SNI `paulislava.space`, завершает TLS на 127.0.0.1:18451 и направляет запросы через FRP. Сертификат обслуживает certbot. Шаблоны nginx: `scripts/web-reserve/nginx-*.conf`; stream map находится в `/etc/nginx/siestanet-reality-stream.conf`. Существующие VPN SNI-маршруты сохранять.

## Медиа

Старый Beget S3 недоступен: credential отклонён, оригиналы в резерве не найдены. Из writable layer старого сайта восстановлены 552 файла Next image cache (17,6 МБ) со сверкой SHA-256. Каталог `/opt/web/image-cache` находится в WSL на E и монтируется в контейнер. В нём есть все 180 вариантов srcset для видимых изображений главной в исходном формате. Nginx передаёт пустой Accept для `/_next/image`, чтобы использовать сохранённые PNG/JPEG. Из кеша восстановлены 58 точно сопоставленных URL в S3 `paulislava-media`; для 10 из них был только WebP, поэтому WebP сохранён дополнительно в `recovered/next-cache/`, а совместимая копия преобразована в формат прежнего URL. У трёх изображений доступное разрешение меньше исходного. Все 68 объектов проверены по публичному HTTPS, MIME, размерам и SHA-256; 18 ранее существовавших объектов не изменены. Из 359 известных URL 283 не имеют точного соответствия в кеше. Это восстановленные копии, а не оригиналы S3. Полный отчёт и подтверждения находятся на ПК в `E:\Services\PaulislavaWeb\migration\cdn-recovery-20261117\`.

## Proff

`PaulislavaProff` — отдельная Windows-служба LocalService с Caddy и PHP FastCGI, расположенная в `E:\Services\PaulislavaProff`; HTTP и FastCGI слушают только loopback 13001 и 13002. `PaulislavaProffFRP` использует отдельную identity и loopback 24009 на VPN-сервере. Nginx направляет `/proff/` в этот сервис. Исходная копия `E:\backup` сохранена; изменяемые файлы `Proff.exe`, `db.mdb`, `program.php` находятся в `data\proff`. Исходная таблица MariaDB `user_proff.accounts` в доступном резерве и дампах не найдена; проверка входа пользователей недоступна до восстановления данных. Не создавать фиктивную таблицу и не заменять рабочую базу старым дампом.

Загрузчик `uploadupdate.php` сохраняет существующий пароль и проверяет его сравнением. Некорректные значения пароля и версии отклоняются. Скрипт `loaddb.php` сохраняет прежнюю проверку session. Исполняемые файлы и конфигурация недоступны для изменения службой; отдельный каталог данных доступен для обновлений. Настройки и credentials вне Git, с закрытыми ACL. Скрипты: `scripts/proff-reserve/`.

## Проверки и сопровождение

Проверены публичные HTTPS, `/api/health`, главная, 18 уникальных изображений главной, `/proff/`, запрет чтения config и отказ загрузчика без пароля. Проверены authenticated GraphQL CMS, два последовательных обновления каждого типа с неизменными SHA-256 и отрицательные проверки пароля. Для обеих служб проверены Stop/Start/Restart и восстановление после сбоя; для Web также холодный старт отдельного WSL без автоматического запуска Docker. После перезапуска FRP проверен публичный HTTPS. Физическая перезагрузка ПК и отправка почты не проверялись. Восстановлены оптимизированные копии, не оригиналы изображений.

Старый deploy Web в GitHub Actions включается только при `WEB_DEPLOY_TARGET=legacy`; автоматический deploy на ПК не настроен. Перед push или обновлением создавать и проверять новый дамп CMS. Исходный резерв и резервные копии сохранять. Интерактивная проверка Chrome не завершена: расширение управления сообщило `Debugger unattached`.
