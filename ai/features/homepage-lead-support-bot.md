# Единая форма заявок и доставка в support-bot

Дата: 2026-10-10.

## Поведение

- На главной в первом экране и в шапке есть «Обсудить проект». Кнопка открывает ту же модальную форму, что используется на странице разработки для компаний: сначала один контакт, затем необязательные подробности и окно успеха.
- В мобильной шапке вместо текста кнопки показана иконка телефона. Подпись `| @paulislava` скрыта. Пункты «Контакт» и «Заказать разработку» убраны из меню; прежняя кнопка «Связаться» убрана из первого экрана.
- Форма внизу главной и форма на странице проекта продолжают работать через тот же `/api/contact`.

## Доставка

- API отправляет каждую заявку и дополнение к ней по SMTP и в `@paulislava/support-bot` через `POST /v1/messages` сервиса `PaulIsLavaSpace`.
- Ключ сервиса хранится в GitHub Secret `SUPPORT_SERVICE_KEY` и закрытом окружении support-bot; сайт получает его только на сервере при деплое. В браузер ключ не попадает.
- `userId` вычисляется как HMAC контакта с ключом сервиса, поэтому повторные сообщения одного контакта попадают в одну тему без хранения контакта в идентификаторе. `requestId` связывает контакт и подробности и защищает сообщение в боте от повтора.
- Успех возвращается после подтверждения SMTP и support-bot. Если SMTP подтвердил письмо, а бот ответил ошибкой, API сообщает об этом, чтобы сбой не оставался скрытым. При повторной отправке в таком случае письмо может продублироваться.
- Ответы оператора в теме бота не отправляются посетителю сайта автоматически: для ответа используется оставленный контакт.

## Проверка

- Локальная сборка Next.js и проверка типов прошли.
- На production проверены главная, мобильная шапка, модальная форма, отправка контакта и подробностей. Обе части тестовой заявки появились в истории support-bot под одним `userId`; API формы показал последовательные экраны успеха.
