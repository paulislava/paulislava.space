# Микроразметка всех основных страниц

Дата: 2026-10-23

## Поведение

Сайт отдаёт JSON-LD в первоначальном HTML. Общий граф `Person` и `WebSite` связан стабильными `@id` с графами отдельных страниц:

| Страница | Типы |
|---|---|
| Главная | `ProfilePage`, `ItemList` проектов и текущей вкладки публикаций |
| Каталоги статей, проектов и циклов | `CollectionPage`, `ItemList`, `BreadcrumbList` |
| Статья | `WebPage`, `BlogPosting`, `BreadcrumbList`; `FAQPage` при наличии полных FAQ-пар в CMS |
| Новость | `WebPage`, `NewsArticle`, `BreadcrumbList` |
| Проект | `WebPage`, `CreativeWork`, `BreadcrumbList` |
| Цикл | `CollectionPage`, `CreativeWorkSeries`, упорядоченный `ItemList`, `BreadcrumbList` |
| Разработка для бизнеса | `WebPage`, три `Service`, `BreadcrumbList` |

Каталоги учитывают `tag` и `tech` на сервере. Карточки и разметка строятся из одного отфильтрованного массива; после клиентского перехода они обновляются вместе. Канонический URL каталога не содержит фильтров. На главной список публикаций соответствует активной вкладке.

## Данные и безопасность

- Общий компонент `JsonLd` использует `serializeJsonLd`: все `<` заменяются на `\u003c`, поэтому текст CMS не может закрыть элемент `<script>`.
- GraphQL-запросы статей и новостей читают `updatedAt`; обновлены frontend-типы и соответствующие generated operations.
- `dateModified` берётся из достоверного `updatedAt`. Недопустимые даты и даты обновления раньше публикации опускаются: у Strapi публикация может происходить после последнего редактирования черновика.
- Дата новости соответствует уже отображаемому `createdAt`; дата статьи — отображаемому `publishedAt` с прежним резервом на `createdAt`.
- В `image` используются реальные медиа CMS. Стандартная обложка интерфейса не подставляется в разметку. Размеры исходного файла не приписываются уменьшенному варианту.
- `primaryImageOfPage` указывает только на реальную обложку, отображаемую на странице с учётом `pageCover` и `showCoverOnPage`. Скриншоты проекта добавляются без повторов URL.
- FAQ строится только из секций CMS, отображаемых `ArticleSections`, с непустыми вопросом и ответом. Новые публикации и FAQ для тестирования на проде не создаются.
- Тексты трёх услуг общие для интерфейса и JSON-LD. Цены, рейтинги и отзывы не выдумываются.

Публичные API и схемы CMS не изменены; миграций БД нет. Generated-файл обновлён только для затронутых операций, без посторонних изменений схемы «Водомера».

## Проверка

`npm run test:seo --workspace=packages/web` — 12 регрессионных проверок, Node.js 22.6+ с нативным удалением TypeScript-типов; дополнительных зависимостей нет. Production-приложение по-прежнему собирается в существующем Node.js 20 Docker-образе.

Успешно прошли TypeScript, ESLint изменённых файлов без предупреждений и production-сборка. Внешний Schema Markup Validator не обнаружил ошибок/предупреждений на главной; также проверены графы статьи, проекта, цикла и услуг.

На проде проверены 36 адресов: все 8 статей и 19 проектов из sitemap, главная, услуга, каталоги, цикл, фильтры и 404. В браузере фильтр React показал 8 карточек и соответствующий список из 8 элементов JSON-LD. На момент проверки опубликованных новостей и FAQ нет; их обработка покрыта тестовыми данными.

Google Rich Results Test проверил публичный URL статьи: два элемента без ошибок — статья и хлебные крошки. У статьи без собственной обложки остаётся необязательное замечание `image`; стандартная заглушка не выдаётся за содержательное изображение.

- [Google: результат проверки опубликованной статьи](https://search.google.com/test/rich-results/result?id=vFQkBL96tA1Gz-JkZH5Rig)
- [CI/CD](https://github.com/paulislava/paulislava.space/actions/runs/39949049046) — все шесть стадий завершились успешно.
- Выпущенный коммит: `8b818ca6d6d35ebe386fc252e3ade1bdc9de1ca6`; на сервере подтверждён работающий web-образ с этим тегом.

Корректная разметка не гарантирует расширенного сниппета или срока переиндексации. Для FAQ личного сайта Google не обещает FAQ-сниппет: это семантическое описание существующего контента.
